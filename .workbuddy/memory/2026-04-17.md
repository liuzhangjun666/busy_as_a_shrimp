## 赛博分身技术选型：OpenClaw vs Hermes Agent

### 分析背景
用户提出赛博分身功能通过 OpenClaw 和 Hermes 实现，需要分析哪个更适合项目。

### 调研结果
1. **OpenClaw**：31.6万Stars，Playwright+CDP浏览器自动化成熟，3万Skills生态，但无原生反检测能力，仅支持OpenAI模型
2. **Hermes Agent**（Nous Research）：6万Stars（增长快），MIT完全开源，内置Camofox反检测（Firefox C++指纹伪装），200+模型可选，自进化Skill系统，子Agent并行，但浏览器操作不如OpenClaw成熟，780个open issues

### 关键发现
- Hermes的Camofox解决了项目最大痛点：目标平台反爬/AI检测
- Hermes模型无关架构（智谱/Kimi/MiniMax）使API成本降低3-5倍
- OpenClaw的Playwright集成在高精度表单操作上更稳定
- 两者不是替代关系，而是互补

### 选型决策（最终版）
- ⚠️ **纠正**：之前说"OpenClaw 有 Camofox 插件"是不准确的。经查证 OpenClaw 插件生态中不存在 Camofox/Camoufox 插件
- **Camoufox 实际信息**：独立 Python 库（PyPI: camoufox, 7.4k⭐, 作者 daijro/Clover Labs），基于 Firefox + Juggler，C++ 层指纹伪装，支持 Remote Server 模式（WebSocket）
- Hermes 内置 Camoufox 作为 6 种浏览器引擎之一（Browserbase/Browser Use/Firecrawl/Camofox/CDP/agent-browser）
- OpenClaw 无内置反检测，要获得需自建 Camoufox Remote Server 集成（非开箱即用）
- **最终方案：Hermes 为主**
  - 理由1：反检测是赛博分身生死线，Hermes 内置 Camoufox 开箱即用，OpenClaw 裸奔
  - 理由2：MCP 适配可控（stdio→HTTP 用 mcp-proxy/supergateway 桥接）
  - 理由3：浏览器基础操作对赛博分身场景够用（浏览/搜索/提取/点击）
  - 风险：Camoufox 2026 新版本实验性，Hermes 780 open issues
  - 缓解：生产用 Browserbase/CDP 稳定模式，反检测场景切 Camoufox
- 保留 OpenClaw 作为精确操作备选（拖拽/PDF/下载场景）
- DeerFlow Skill 路由：日常反检测浏览→Hermes Camoufox，精确数据操作→OpenClaw

## DeerFlow Skill 实现方案（2026-04-17 下午）

### 关键发现
- DeerFlow Skill 本质是"给 AI Agent 看的入职培训手册"（SKILL.md Markdown 文件），不是代码/配置
- Skill 通过 YAML frontmatter 的 description 字段触发（关键词匹配）
- OpenClaw 的 MCP Server 端点暴露的是文档搜索工具，不是浏览器自动化工具
- 浏览器自动化是 OpenClaw 的 REST API（navigate/click/type/snapshot/evaluate），不是 MCP 协议

### 两种集成路径
- **路径 A（推荐先做）**：SKILL.md 中直接写 OpenClaw REST API 调用指令，Agent 用 web_fetch/HTTP 调用
- **路径 B（长期正确）**：自建 Python MCP Server 封装 OpenClaw REST API 为标准 MCP 工具

### 需要创建的文件
- `skills/custom/lobster-cyber-scan/SKILL.md` — 主 Skill（5阶段执行方法论）
- `skills/custom/lobster-cyber-scan/references/1688-guide.md` — 1688 采集策略
- `skills/custom/lobster-cyber-scan/references/xiaohongshu-guide.md` — 小红书采集策略
- `skills/custom/lobster-cyber-scan/references/review-protocol.md` — 人工审核协议
- `skills/custom/lobster-cyber-scan/scripts/format-opportunity.py` — 格式化脚本
- `skills/custom/lobster-smart-matcher/SKILL.md` — 智能匹配辅助 Skill
- `extensions_config.json` — 注册 Skill 和 MCP Server

### 赛博分身未实现功能归属
- NestJS 后端 5 个：审核通知推送/积分-HP联动/内容人性化/偏好反馈/Redis队列锁
- DeerFlow 侧 2 个：Skill 定义 + 浏览器自动化MCP调用
- 基础设施层 4 个：反检测/住宅代理/行为变异/指纹隔离
- 前端 2 个：分身控制台/审核弹窗

## DeerFlow → Hermes Agent 集成方案（2026-04-17 晚）

### 核心架构决策
- **最终方案：Hermes Agent 替代 OpenClaw 作为 DeerFlow 的浏览器执行层**
- Hermes 内置 6 种浏览器引擎（Playwright/Camoufox/Browserbase/CDP/Puppeteer/Custom）
- Hermes 原生支持 MCP Server，DeerFlow 可通过标准 MCP 协议调度
- 不再需要自建 Python MCP Server 适配层

### 关键技术点
1. **DeerFlow 注册 Hermes MCP**：extensions_config.json 的 mcpServers 配置 hermes-browser
2. **SKILL.md 工具调用变更**：从 `POST http://localhost:18789/api/browser/navigate` → `browser_navigate` (MCP工具)
3. **Hermes 安装命令**：`curl -fsSL https://res1.hermesagent.org.cn/install.sh | bash`
4. **浏览器引擎选择**：通用→Playwright，反检测→Camoufox，换IP→Browserbase云模式
5. **Hermes Skill 与 DeerFlow Skill 区别**：Hermes 有自改进循环（越用越聪明），DeerFlow Skill 是静态Markdown

### 服务器操作步骤
1. 安装 Hermes Agent
2. 配置浏览器引擎（playwright/camoufax）
3. 创建 Hermes Skill 文件（lobster-browser/SKILL.md）
4. 更新 DeerFlow extensions_config.json（注册 Hermes MCP）
5. 更新 lobster-cyber-scan SKILL.md（REST API → MCP 工具）
6. 重启 DeerFlow 验证
7. 端到端测试

- 第二阶段（1-2周后）：切换到 Hermes MCP 标准（Path B）
